## The T-05 gap (reason for DONE_WITH_CONCERNS)

The brief assumes `acp.rs` already contains the T-05 permission bridge. It does
not: the working tree holds T-00..T-04 only; T-05 has a brief but **no report
and no integrated code** — `acp_permission.rs` (T-06, DONE per its report) is
still unregistered. Consequences handled as follows:

1. **"deny semua pending permission waiters (jalur T-05)"** — no waiter map
   exists yet. Implemented as the wired no-op seam
   `AcpService::deny_pending_permissions()` (called in the teardown, before the
   joins, exactly where T-05 must hook its deny loop). Documented in-code.
2. **Test `eof_during_pending_permission_unblocks`** — cannot exist without the
   T-05 gate. Instead: `eof_during_pending_confirmation_unblocks_the_turn`
   stages a real `Event::ConfirmationRequest` mid-turn through the real adapter
   paths and proves EOF unwinds a turn parked behind an engine awaiting client
   word. The true permission variant slots in once T-05 lands.
3. Everything else in the brief is T-05-independent and is fully implemented.

## Implementation (`takka-runtime/src/acp.rs` unless noted)

- `SHUTDOWN_JOIN_TIMEOUT = 15s` (brief range 15–30s; chosen 15s) — bound for
  the whole teardown join.
- `serve_over` → extracted `framing_loop(&service, reader)`; on EOF the loop
  calls `AcpService::shutdown()` before `Ok(())`. `main` behavior unchanged:
  exit code 0 on `Ok` (proven end-to-end by the subprocess test + a manual run).
- `shutdown()` ordering (each step matters):
  1. cooperative cancel for every live session (`cancel_requested` flag +
     `Request::Cancel`; dead engines' send errors ignored);
  2. `deny_pending_permissions()` (T-05 seam, see above);
  3. `closed` flag set **under the registry lock** + `drain()` — closes the
     boot-vs-drain race: a `session/new` finishing concurrently either inserts
     before the drain (teardown owns it) or is refused and its engine exits on
     its own when the failed session drops the senders;
  4. join TURN threads first — each holds a `req_tx` clone, and the engine only
     observes EOF once every sender is gone;
  5. drop sessions (last senders die → idle engines exit on
     `read_request → Ok(None)`), then bounded-join engine threads.
- `join_bounded(handles, deadline, probe)`: port of the daemon pattern
  (`daemon.rs:377`); stragglers are detached with `tracing::warn!` and the
  process still exits. One deadline for the whole teardown.
- Thread handles parked on `Session`: `engine: Mutex<Option<JoinHandle>>`
  (set at boot), `turn: Mutex<Option<JoinHandle>>` (set by `session_prompt`).
- Probe: `AcpService.joined_probe: Option<Arc<AtomicUsize>>`, `#[cfg(test)]`
  only, bumped after each engine-thread join — the observable "all engines
  joined" signal; production builds compile it out.
- Fake-engine seam (the mechanism the T-05 brief prescribes, reused so the
  T-05 integrator can build on it): `#[cfg(test)] type FakeEngine`,
  `#[cfg(test)] serve_over_test(reader, sink, config, fake_engine, probe)` and
  `AcpService.spawn_engine` which swaps the real `RuntimeEngine` boot for the
  scripted thread when the seam is installed. Production behavior untouched
  (`spawn_engine_thread` is the only path in non-test builds).
- `TAKKA_TEST_ACP_CONFIG`: TEST-ONLY pin (comment: "never set in production")
  applied in `serve_with_config`, so both entries (`serve()` and the flag path)
  honor it. It replaces `AcpConfig.config_path` for every session engine.
- `main.rs`: `parse_acp_flags` hand-parses `--acp [--acp-max-sessions N]` in
  the style of `parse_daemon_flags`; portable (no `#[cfg(unix)]` — the ACP
  adapter is stdio, per T-08). Without the override, `main` still calls plain
  `serve()` (byte-identical behavior to pre-T-07); with it,
  `serve_with_config(config)`. Bad values → exit 2 with a one-line message
  (verified manually: non-number, missing value, unknown flag).

## Self-review findings

- Join order is load-bearing and documented in `shutdown`'s doc comment: turns
  before engines, because a turn thread's `Arc<Session>` keeps a `req_tx` alive
  and the engine only sees `Ok(None)` after the last sender drops.
- The `closed` flag is a small addition beyond the brief's literal text, but it
  is what makes "drain" actually mean "no engine escapes the join": without it,
  a boot finishing during the drain would insert after it and leak past the
  join. An engine refused by the closed check is *not* joined (it exits on its
  own once its senders drop); acceptable because the process is exiting anyway.
- Probe is `#[cfg(test)]`-gated; `cargo check` without `--tests` confirms the
  production build has no test machinery (checked: zero warnings).
- `deny_pending_permissions` is deliberately a no-op — implementing the waiter
  map now would duplicate/conflict with the T-05 lane's deliverable (YAGNI).

## Concerns

1. **T-05 is not integrated** (the gap above). The true
   `eof_during_pending_permission_unblocks` test and the real waiter-deny must
   land with that lane; the seam positions are marked in code.
2. The straggler/detach path of `join_bounded` is not directly tested (a test
   would need a thread parked >15s, breaking the ≤10s test bound). Same shape
   as the daemon's `join_bounded`, which is also untested for the straggler arm.
3. `--acp-max-sessions 0` parses fine and simply rejects every `session/new`
   (capacity semantics). No special validation — kept as the "small helper" the
   brief asked for.
4. An engine refused by the closed-check during EOF-vs-boot is not joined
   (point 2 of self-review); it self-exits. Only observable in a narrow race;
   documented, not tested (timing-dependent).
5. `serve()` now exists without a production caller on the flag path when
   `--acp-max-sessions` is given; the no-flag path still routes through it, so
   it remains live code (no dead-code warning).
