## 1. Event baru (D12)

Di `takka-core/src/events.rs`:

```rust
/// Emitted when a turn ends because a limit was reached (D12, ACP Fase 4).
/// Additive: no protocol bump (same precedent as `Usage`/`SessionAdopted`).
#[serde(rename = "turn_limit_exceeded")]
#[serde(rename_all = "snake_case")]  // pakai bentuk yang konsisten dgn variant lain
TurnLimitExceeded { kind: TurnLimitKind },

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum TurnLimitKind {
    /// Provider stopped the response at its output-token cap.
    MaxTokens,
    /// The agent loop hit `max_iterations` (one user turn = N agent requests).
    MaxTurnRequests,
}
```

Lengkapi: `EventType::TurnLimitExceeded`, arm di `event_type()`, dan entri test
nama wire snake_case yang sudah ada (`turn_limit_exceeded`) bila daftar itu
menyebutkan semua varian.

## 2. Titik emisi (empat tempat, hati-hati jangan dobel)

Helper privat di `run.rs`:

```rust
/// Providers report truncation with different spellings (OpenAI `length`,
/// Anthropic `max_tokens`, Google `MAX_TOKENS`).
fn is_token_truncated(finish_reason: Option<&str>) -> bool
```

- **MaxTurnRequests**: di KEdua branch `if finalizing { ... }` (sync + stream),
  emit `Event::TurnLimitExceeded { kind: MaxTurnRequests }` SEBELUM
  `return Ok(...)`. Jangan juga emit di tempat lain.
- **MaxTokens**: di KEdua branch "final answer accepted" (sync: else tanpa tool
  calls; stream: padanannya) emit
  `Event::TurnLimitExceeded { kind: MaxTokens }` HANYA bila
  `is_token_truncated(finish_reason)` benar. Stream: track `finish_reason` dari
  chunk terakhir (`chunk.finish_reason`), simpan di variabel lokal.
- Jangan mengubah perilaku return/isi jawaban. Hanya menambah event.
- Tambahkan test: (a) `finalizing` → event MaxTurnRequests muncul sekali,
  (b) finish_reason "length" → MaxTokens, (c) finish_reason "stop" → tidak ada
  event. Ikuti pola test orchestrator yang ada (mock provider) di
  `takka-core/tests/` atau `#[cfg(test)]` setempat — pakai yang paling murah dan
  sudah ada polanya; jangan menambah dependency.

## 3. `Request::SetPermissionMode` (untuk `session/set_mode` D9)

Engine tak punya jalan ganti mode setelah Init (Init kedua ditolak tanpa token
daemon). Tambahkan request additive:

```rust
/// Ganti permission mode sesi berjalan (ACP `session/set_mode`, D9).
/// Additive: tanpa bump protokol. Berlaku pada turn berikutnya
/// (safety dicek per boundary).
SetPermissionMode { mode: PermissionMode },
```

- Handler di `engine.rs`: `orchestrator.set_permission_mode(mode)`; simpan juga di
  `current_overrides.permission_mode` (supaya konsisten bila diobservasi);
  ACR: emit `Event::PermissionModeChanged { mode }` (event baru, additive,
  snake_case `permission_mode_changed`) supaya frontend bisa menampilkan status.
  Jika belum initialized → `Event::Error { message: "not initialized" }` seperti
  request lain.
- `PermissionMode` sudah `Serialize`/`Deserialize` (lihat `safety/risk.rs`);
  pastikan bentuk wire-nya `"default"|"plan"|"yolo"`.
- JANGAN mengubah `Init`/adopt/daemon token apa pun (D10: engine tak berubah
  perilaku; ini hanya permukaan request baru).
