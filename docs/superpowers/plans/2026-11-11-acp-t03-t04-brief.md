## YanG diimplementasikan

### T-03 — session lifecycle
- Refactor servis ke bentuk testable: `serve()` + `serve_with_config(AcpConfig)` →
  frim loop; tambahkan seam `serve_over(reader: &mut dyn BufRead, sink: Arc<dyn AcpSink>,
  config)` agar test bisa jalan tanpa stdio. Sink trait: satuan `send_line(&Value)`.
- Registry sesi: `session/new` → validasi cwd == `std::env::current_dir()` (D11:
  mismatch = error invalid_params + pesan aksionable "restart the agent from project
  directory X"), boot 1 engine per sesi (D6), kirim `Request::Init` dengan
  `InitOverrides { config_path: config test (bisa dari AcpConfig), permission_mode: None }`,
  tunggu `InitOk` (jika `Error` event → propagasikan sebagai JSON-RPC error).
- Advertise mode sesi (D9) di NewSessionResponse.modes: `default/plan/yolo`
  (mapping `takka_core::PermissionMode`), current = default.
- `session/prompt`: content blocks → 1 task string + attachments
  (`Text` → teks; `Image` wajib mime `image/{png,jpeg,gif,webp}` → `Attachment`
  kind Image, `AttachmentSource::DataUrl`, data_base64; `ResourceLink`/`Resource`/
  `Audio` → error invalid_params "unsupported content type" + hint). Prompt kosong
  → invalid_params. Kemudian jalankan turn di thread tersendiri (framing loop harus
  tetap respon terhadap `session/cancel`): busy gate per sesi (turn kedua saat
  berjalan → error JSON-RPC "session busy"), kirim `Request::Run`, drain engine
  events, translasi via `TranslatorState::translate` → kirim notification
  `session/update` per event, sampai terminal (`Done` → stopReason end_turn;
  `Error` → JSON-RPC error dengan pesan; engine mati → error + teardown sesi).
  Buka kembali channel event sesudah terminal (receiver park/unpark dengan
  Mutex<Option<Receiver>>) supaya sesi tetap reusable — T-03 expect: turn gagal
  bersih, prompt KEDUA masih bekerja (tidak ada poisoned session).
- `session/cancel` (notification): untuk saat ini cukup diterima kooperatif
  (set flag + kirim `Request::Cancel`), mapping lengkap `stopReason: cancelled`
  adalah lane T-05 — jangan implementasi lebih dari wiring minimum, tapi JANGAN
  hancurkan sesi saat cancel.
- Hapus stub `before_sessions` & error "pre-T-03"; `session/load` tetap ditolak
  dengan error jujur ("session/load is phase 2 (loadSession capability not advertised)").
- EOF semua kegiatan: return clean `Ok(())` (T-07 lane yang akan melengkapi join).

### T-04 — over-capacity
- `AcpConfig { max_sessions }` (default 4 = `DEFAULT_MAX_SESSIONS`); slot diambil
  saat `session/new`; penumpang ke-N+1 → JSON-RPC error `invalid_request`, data
  `{ method: "session/new", reason: "session capacity reached", capacity: N }`.
- Parse flag `--acp-max-sessions N` boleh ditambah di `takka-runtime/src/main.rs`
  SIAPKAN sebagai catatan di laporan saja — jangan edit main.rs (file lain
  sedang dikerjakan lane paralel). Struktur `serve_with_config` sudah cukup untuk
  wiring flag oleh integrator.

## Aturan test (hermetik)

- TIDAK membaca ambient config. Config test: file sementara seperti
  `hermetic_runtime_config_at("http://127.0.0.1:9")` dari takka-cli; test
  menyuntik masuk lewat `AcpConfig`/`serve_over` — bukan env var global.
- TIDAK SPAWN provider asli. `127.0.0.1:9` = connection refused instan.
- Semua test dengan deadline bound (maks 10 dtk seluruh assertion) — lihat pola
  `POLL_TIMEOUT` di daemon.rs tests. Test jalan di 3 OS (unix/non-unix aman).
- Test T-03 minimal (mod tests di acp.rs):
  1. session/new (cwd = current_dir) → `sessionId` ada, modes advertised
     (default/plan/yolo, current default), engine ter-boot (tunggu InitOk implisit).
  2. session/prompt dengan provider unreachable → turn selesai CEPAT, respons
     prompt berisi error (turn fails cleanly), sesi masih bisa prompt lagi
     (kirim prompt kedua → masih dijawab, tidak hang).
  3. session/new dengan cwd lain → error, data memuat pesan "restart the agent".
  4. session/prompt dengan resource_link → error unsupported content type.
  5. prompt sebelum session → error session not found.
- Test T-04:
  6. kapasitas = 1; session/new kedua → error "session capacity reached".
- Uji wiring test-nya juga kalau sempat (opsional): satu smoke test subprocess
  `takka-runtime --acp` melalui `env!("CARGO_BIN_EXE_takka-runtime")` dengan
  `TAKKA_TEST_ACP_CONFIG` (jika melakukan ini, sediakan env-var override path
  Hermetik di `serve()`), atau cukup uji `serve_over` in-process. Pilih salah satu,
