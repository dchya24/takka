## Yang diimplementasikan

### 1. Prompt resolves `cancelled` (inti T-05)
- Track satu flag per turn (sudah ada `Session.cancel_requested`). Di turn loop
  (`run_prompt_turn`): terminal `Event::Error` saat flag set → respons
  `Ok(acp::PromptResponse::new(acp::StopReason::Cancelled))`, BUKAN error JSON-RPC.
- Sesi harus pulih kembali: busy turun, receiver diparkir ulang, prompt berikutnya
  berjalan normal (tidak menghancurkan sesi, tidak meracuni state).
- `session/cancel` untuk session tidak diketahui → tetap silence.

### 2. Permission bridge di turn loop (integrasi T-06)
- `AcpService` simpan pending permission waiters:
  `Mutex<HashMap<String outbound_id, mpsc::SyncSender<bool>>>`.
- Saat engine memancarkan `Event::ConfirmationRequest { action, description, .. }`:
  bangun `acp_permission::permission_request(session_id, outbound_id, action,
  &description)` (id unik `format!("acp-perm-{n}")`, counter per service), kirim
  frame `{"jsonrpc":"2.0","id":outbound_id,"method":"session/request_permission",
  "params": ...}` lewat sink, parkir waiter, dan BLOK menunggu jawaban.
- Jawaban datang sebagai frame result klien (id = outbound_id, tanpa `method`):
  tambahkan routing `route_client_response(frame)` di handle_frame — parse
  `acp::Response`: `outcome` → `acp_permission::outcome_approves()`, misal error →
  deny. Kirim bool ke channel waiter, hapus dari map.
- Setelah jawaban masuk: `req_tx.send(ProtocolRequest::new(...,
  acp_permission::confirm_response(None, approved)))` — engine unblock dan turn
  berlanjut secara normal.
- Cancel saat permission pending: `session_cancel` harus membebaskan waiter
  (deny semua pending untuk itu sesi) SEBELUM/SETELAH forward `Request::Cancel` —
  kalau tidak, turn loop dead-lock menunggu jawaban.
- Register module: tambahkan `mod acp_permission;` di `main.rs` (jika ada
  `#![allow(dead_code)]` di file T-06, boleh dibiarkan sampai fungsi semua
  dipakai — cek hasil clippy).

### 3. Test (hermetik — nothing real, deadline semua ≤10s; ikuti pola
       `VecSink`/`ChanReader` yang sudah ada)

Turn dengan engine harus deterministik. Pilihan yang diizinkan (pilih paling clean,
jelaskan di laporan):
- **Fake-engine seam (disarankan)**: di `mod tests`, bangun sesi secara manual —
  buat channels sendiri (`mpsc::channel::<ProtocolRequest>()` + `channel::<
  ProtocolEvent>()`), spawn thread "engine" tiruan yang: baca `Init` → kirim
  `InitOk`; baca `Run` → emit event tersuai; baca `ConfirmResponse` → catat; dst.
  Supaya bisa lewat jalan publik `serve_over`, tambahkan seam `#[cfg(test)]` kecil
  pada `AcpConfig` (mis. `test_engine_factory: Option<...>` atau constructor
  `AcpService::with_boot_override`) — tidak boleh mengubah perilaku production.
- Atau port server SSE scripted dari `takka-cli/src/commands.rs` e2e tests
  (`hermetic_runtime_config_at(api_base)` menambeng provider lokal).

Wajib tercover:
1. `cancel_mid_turn_resolves_cancelled`: prompt jalan lama (fake stream / SSE
   delay), `session/cancel` dikirim mid-turn → respons prompt
   `stopReason: "cancelled"`; lanjut prompt kedua → dijawab (sesi pulih).
2. `cancel_during_pending_permission_does_not_deadlock`: engine pause di
   `ConfirmationRequest` → adapter sudah kirim `session/request_permission`; test
   kirim `session/cancel` alih-alih jawaban permission → permission waiter di-deny,
   turn tetap selesai `cancelled` (bounded, tidak hang).
3. `permission_allow_and_confirm_response_flow`: engine emit `ConfirmationRequest` →
   sink punya frame `session/request_permission` (assert wire shape: sessionId,
   toolCall.toolCallId/kind, options allow_once+reject_once); test membalas
   `Selected(allow_once)` dengan id sesuai → assert engine menerima
   `ConfirmResponse { approved: true }` (fake engine/catatan), lalu `Done` →
   `stopReason: end_turn`.
4. `permission_reject_routes_false`: jawab `reject_once` → `ConfirmResponse
   approved=false` sampai engine.
5. `client_result_frames_never_get_replies` (jaga kontrak JSON-RPC).
